# FINN — fork and component review

14 November 2026. All six forks were inspected through the GitHub plugin: repository metadata, actual licence files, package manifests and relevant API source/docs. Links below pin the inspected commits. These are static compatibility checks; no fork was cloned, installed, executed or modified. A fork's manifest version does not establish that the same release is published or that a combined dependency lock resolves.

Licence choice is not a claim that GPL software is unusable. The narrow independent adapter avoids an unnecessary dependency and its licence obligations. Retain required copyright/licence notices for any reused code. Software licences do not grant market-data or document redistribution rights; link original reports and keep public excerpts limited. Transitive dependency notices are checked when locking the implementation.

## API and compatibility findings

**yfinance — manifest version 1.8.0.** [history implementation](https://github.com/aadishjainiitd-svg/yfinance/blob/2492a853aee975b4f39f230ad763298f039e37ae/yfinance/scrapers/history.py) supports `Ticker(...).history(period="3mo", interval="1d", auto_adjust=False, actions=True)`; `auto_adjust` defaults to true and date `end` is exclusive. Its `raise_errors` argument is deprecated. An alternative adapter would explicitly set price basis and handle empty frames, rather than trust defaults. [Manifest](https://github.com/aadishjainiitd-svg/yfinance/blob/2492a853aee975b4f39f230ad763298f039e37ae/pyproject.toml) includes Python 3.12 support and pandas, NumPy and curl_cffi dependencies; Linux wheel resolution remains untested. It uses the same Yahoo source as the direct endpoint, so switching libraries is not an independent data fallback. [README](https://github.com/aadishjainiitd-svg/yfinance/blob/2492a853aee975b4f39f230ad763298f039e37ae/README.md) calls the project unofficial and describes Yahoo data as intended for personal use; public-demo data rights remain separate from Apache licensing.

**NseIndiaApi — package nse 5.1.2, Python ≥3.8.** [NSE source](https://github.com/aadishjainiitd-svg/NseIndiaApi/blob/9af4cb2c30590bed7306f9b63af963fc1614d031/src/nse/NSE.py) exposes `NSE(download_folder, ...)`, `announcements(index="equities", symbol=..., from_date=..., to_date=...)` and `annual_reports(symbol, segment="equities")`. It needs a writable download/cookie location and makes network/session requests. [Manifest](https://github.com/aadishjainiitd-svg/NseIndiaApi/blob/9af4cb2c30590bed7306f9b63af963fc1614d031/pyproject.toml) uses httpx and rate limiting. These APIs do not guarantee NSE accepts cloud-host traffic. The independently written FINN adapter must bound dates, throttle, handle cookies/403/429 and preserve exchange IDs.

**Docling — docling-slim 2.150.0, Python ≥3.10,<4.** [DocumentConverter](https://github.com/aadishjainiitd-svg/docling/blob/31d14a74b7bddc850541ab8363b8585085845313/docling/document_converter.py) provides `DocumentConverter().convert(source, max_num_pages=..., max_file_size=...)`; the result's document can export Markdown. The [modular manifest](https://github.com/aadishjainiitd-svg/docling/blob/31d14a74b7bddc850541ab8363b8585085845313/pyproject.toml) separates base, PDF and local-model extras: do not equate the slim base with every ML dependency. Full local conversion may require PyTorch, model artifacts and additional memory; CPU operation is supported, GPU is not mandatory. The [Dockerfile](https://github.com/aadishjainiitd-svg/docling/blob/31d14a74b7bddc850541ab8363b8585085845313/Dockerfile) illustrates CPU/model-cache setup. Model weights may have licences separate from the code. None of this is justified by the sampled text PDFs yet.

**LlamaIndex — 0.14.26, Python ≥3.11,<4.** [CitationQueryEngine.from_args](https://github.com/aadishjainiitd-svg/llama_index/blob/99d7433f6f71888951379ccca9294e272442c832/llama-index-core/llama_index/core/query_engine/citation_query_engine.py) can construct a cited query engine, but numbered citation chunks are not automatically verified PDF-page provenance. [Starter package](https://github.com/aadishjainiitd-svg/llama_index/blob/99d7433f6f71888951379ccca9294e272442c832/pyproject.toml) pulls OpenAI integrations; a core-only build can configure other providers and does not inherently require OpenAI. Python 3.12 is within the declared range. Keeping retrieval local avoids extra provider, embedding and metadata plumbing in this build.

**Instructor — 1.18.0, Python ≥3.10,<4.** [from_provider docs](https://github.com/aadishjainiitd-svg/instructor/blob/2549049be07ec3be1d617f8904ea8ffe18253c48/docs/concepts/from_provider.md) exposes `instructor.from_provider("provider/model")` and `client.create(response_model=..., messages=...)`. Current docs route supported providers through v2 and deprecate legacy provider-specific modes. Groq and Google GenAI factories exist, but mode support differs. [Manifest](https://github.com/aadishjainiitd-svg/instructor/blob/2549049be07ec3be1d617f8904ea8ffe18253c48/pyproject.toml) requires Pydantic ≥2.8,<3 and additional provider extras. Structured output validates shape, not evidence; provider retries would still need coordination.

**ui — source components, not an app runtime.** [Sheet](https://github.com/aadishjainiitd-svg/ui/blob/e62c9435fff729a175f38983dee73b2cb4f6a069/apps/v4/registry/new-york-v4/ui/sheet.tsx) uses React and Radix Dialog with `SheetContent(side="bottom" | "right" | ...)`, title and description. Its styling uses Tailwind and registry aliases, so copying the file unchanged into plain CSS is not compatible. Adapt that one component's styles/imports; keep focus management, Escape and return-focus behavior and test them. [Vite template](https://github.com/aadishjainiitd-svg/ui/blob/e62c9435fff729a175f38983dee73b2cb4f6a069/templates/vite-app/package.json) uses React 19, Vite 8 and Tailwind 4; the entire pnpm/Next.js documentation monorepo is unnecessary. Use the documented [Radix Dialog primitive](https://www.radix-ui.com/primitives/docs/components/dialog) and preserve the existing plain-CSS choice. This is the only proposed fork code reuse.

## Models and deployment

Use direct HTTP adapters behind one synthesis contract: Groq `openai/gpt-oss-120b` first, Gemini `gemini-3.5-flash-lite` as a tested fallback. Groq documents strict JSON-schema support for GPT-OSS; all fields must be required and objects disallow additional properties. Gemini supports a JSON-schema subset, so use a simple shared schema and validate locally. No streamed partial answer is needed. Account entitlement and real quotas are not verified by documentation. [Groq schema API](https://console.groq.com/docs/structured-outputs), [Gemini schema API](https://aistudio.google.com/docs/structured-output), [Gemini model](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite).

Node 24.21 and Python 3.12.14 are available locally; SQLite FTS5 works. Node meets [Vite's documented minimum](https://vite.dev/guide/). Proposed backend packages are not installed or resolved together. At implementation, lock compatible releases, run imports/build in the Linux deployment image and record exact versions; never deploy floating fork branches.

One CPU Linux web service needs outbound HTTPS, temporary writable storage, sufficient measured PDF memory, and a Node build stage plus Python runtime. **The user selected Render Free for this submission.** It sleeps after 15 minutes, takes about a minute to wake and loses runtime files on restart/spin-down. SQLite is a disposable cache, not durable storage. Use a dated demo seed, preserve review state in the browser, and test a cold restart. Account access and available memory remain to be verified; no paid purchase is authorised. [Render limitations](https://render.com/docs/free).

**First gate:** from the chosen host, an uncached unfamiliar ticker must discover and process its primary annual report and transcript and produce a supported answer within the declared resource limits. Local download success and package manifests cannot substitute for this test.

Sequential-review correction: Render documents [512 MB / 0.1 CPU for Free](https://render.com/docs/compute-plans) and [Node/npm in its native runtimes](https://render.com/docs/native-runtimes). Use the native Python runtime with explicit version/build checks; Docker is unnecessary unless the native build fails. Combined parser/API memory remains unmeasured. [Groq's published limits](https://console.groq.com/docs/rate-limits) include 8K TPM for the proposed model; admission must count prompt, evidence and output, rather than relying on RPM. Actual account limits remain unverified. No framework decision changes.
